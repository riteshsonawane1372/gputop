Why gputop

Questions, not dashboards.

Every view exists to answer something you actually ask at 2am.

Which GPU is busy?

OverviewPer-GPU utilization, VRAM, power, temperature, health and state in one dense table.

Which process is eating VRAM?

ProcessesSortable and searchable, resolved through to container, pod and workload.

Why is GPU 4 slow?

GPUs · History · HealthThrottle reasons, PCIe width, Xid events and outlier detection, side by side.

Is this GPU throttling?

Power · ThermalsLive clock-event reasons and the thresholds that triggered them.

Is NVLink healthy?

NVLinkPer-link state, throughput, error counters and topology.

What happened fifteen minutes ago?

HistoryScrub any metric back through time, with events pinned on the timeline.

Which workload owns this GPU?

KubernetesGPU → process → container → pod → workload correlation.

Are we wasting GPUs?

WorkloadsIdle-but-allocated GPUs, stragglers and an efficiency score.

Design rule: no metric without a reason. Unsupported values read N/A, never 0 — and vendor metrics stay distinguishable from gputop-derived ones.

Install

Running in about ten seconds.

No agent, no daemon, no database. One binary you can delete afterwards.

linux · amd64 
$ curl -fLo gputop https://github.com/riteshsonawane1372/gputop/releases/latest/download/gputop-linux-amd64
$ chmod +x gputop && sudo install gputop /usr/local/bin/
$ gputop --demo   # try it with no GPU at all
go 1.25+ 
$ go install github.com/riteshsonawane1372/gputop/cmd/gputop@latest
from source 
$ git clone https://github.com/riteshsonawane1372/gputop
$ cd gputop && make build
$ ./bin/gputop --demo

Also available: gputop --once --json for one machine-readable snapshot, gputop --service for the HTTP API and Prometheus endpoint, and gputop --remote gpu-node-01 to attach to a remote agent.
